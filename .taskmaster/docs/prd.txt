# Product Requirements Document (PRD) for mini-rag

## Project Overview

**mini-rag** is a minimal implementation of the Retrieval-Augmented Generation (RAG) model for question answering. The project allows users to upload documents, process them into chunks, index them into a vector database, and perform semantic search and question answering over the indexed data. It is designed as an educational project, with step-by-step explanations available via a set of Arabic YouTube videos.

## Project Goals

1. Create a simple, functional RAG application with a clean user interface
2. Ensure all API endpoints work correctly according to the documentation
3. Make the application easy to understand and use
4. Implement the MVP features without any unnecessary complexity

## API Endpoints

### 1. Welcome Endpoint
- **URL:** `/api/v1/`
- **Method:** `GET`
- **Description:** Returns the application name and version.

### 2. List All Projects
- **URL:** `/api/v1/projects/`
- **Method:** `GET`
- **Description:** Returns a list of all project IDs.

### 3. Upload Data
- **URL:** `/api/v1/data/upload/{project_id}`
- **Method:** `POST`
- **Description:** Upload a file to a specific project.

### 4. Process Data
- **URL:** `/api/v1/data/process/{project_id}`
- **Method:** `POST`
- **Description:** Process uploaded files for a project, splitting them into chunks and storing them for later retrieval and search.

### 5. Index Push
- **URL:** `/api/v1/nlp/index/push/{project_id}`
- **Method:** `POST`
- **Description:** Indexes the processed chunks of a project into the vector database.

### 6. Index Info
- **URL:** `/api/v1/nlp/index/info/{project_id}`
- **Method:** `GET`
- **Description:** Retrieves information about the vector database collection for a project.

### 7. Index Search
- **URL:** `/api/v1/nlp/index/search/{project_id}`
- **Method:** `POST`
- **Description:** Performs a semantic search over the indexed data for a project.

### 8. Index Answer (RAG)
- **URL:** `/api/v1/nlp/index/answer/{project_id}`
- **Method:** `POST`
- **Description:** Answers a question using Retrieval-Augmented Generation (RAG) over the indexed data for a project.

## Required Features

1. User should be able to create or select a project
2. User should be able to upload documents to a project
3. User should be able to process documents into chunks
4. User should be able to index chunks into the vector database
5. User should be able to search for relevant information in the indexed documents
6. User should be able to ask questions and get answers based on the indexed documents
7. User should be able to see the status of their projects and documents

## Technical Requirements

1. Backend built with FastAPI
2. Frontend built with React
3. Vector database for storing and retrieving document embeddings
4. LLM integration for generating answers to questions
5. Document processing pipeline for extracting text and creating chunks
6. API endpoints for all required functionality

## 4. Vision & Goals
1. **Delightful UX** – Provide a polished interface enabling technical and non-technical users to interact with Mini-RAG in <2 clicks.
2. **Feature Parity** – Expose every v1 API capability with clear user journeys.
3. **Observability** – Visualise ingestion, index status and usage statistics in real-time.
4. **Extensibility** – Modular code-base that supports future tasks such as multi-project management, auth and chat history.

## 5. Target Users
• Data scientists experimenting with RAG workflows.  
• Developers integrating semantic search into apps.  
• Students following the Arabic tutorial series.

## 6. Functional Requirements
FR-1  Dashboard landing page summarising projects, index status & key stats.  
FR-2  Project selector & creator (uses `/projects/`).  
FR-3  Upload centre with drag-and-drop, progress bars & file list (uses `/data/upload/`).  
FR-4  Processing wizard for chunk size/overlap, reset toggle (uses `/data/process/`).  
FR-5  Index management page with "Push to index", "Reset" and collection info (uses `/nlp/index/*`).  
FR-6  Search page with query box, top-k selector, result viewer highlighting passage & metadata.  
FR-7  Q&A chat page with conversation view, source citations and streaming responses.  
FR-8  Global toast notifications & error banners.  
FR-9  Statistics page showing charts (document types, query history etc.).  
FR-10 Health-check & version modal (uses root endpoint).

## 7. Non-Functional Requirements
NFR-1  Responsive layout (mobile, tablet, desktop ≥1280 px).  
NFR-2  Performance: first contentful paint ≤1.5 s on broadband.  
NFR-3  Accessibility (WCAG 2.1 AA).  
NFR-4  Internationalisation ready (en/ar).  
NFR-5  Code quality: ESLint, Prettier, 75 % unit test coverage.  
NFR-6  Security best practices (CORS, no API key leak, input sanitisation).  

## 8. Technical Stack
• React 18 + TypeScript
• Vite build tool  
• Tailwind CSS & shadcn/ui component library  
• React Router  
• React Query (TanStack) for data-fetching & caching  
• Context API (Project context)  
• Victory or Recharts for charts  
• Playwright for e2e tests  
• CI via GitHub Actions (lint → unit → build).

## 9. Architecture & Key Components
1. **API Client Layer** – Typed wrappers for each endpoint, centralised in `src/api/*` (already present but will be hardened).
2. **Context Providers** – `ProjectProvider`, `ThemeProvider`, `ToastProvider`.
3. **Pages** – `Dashboard`, `Upload`, `Process`, `IndexInfo`, `IndexSearch`, `QAPage`, `Settings`, `NotFound`.
4. **Reusable UI** – Buttons, Inputs, Charts, Modals, Skeleton loaders.
5. **Routing** – `/`, `/project/:id/upload`, `/project/:id/search`, etc.
6. **State Machines** – XState or simple reducers for complex flows (processing wizard).

## 11. Success Metrics
• 90 % of API error cases handled gracefully.  
• >80 Google Lighthouse performance & accessibility scores.  
• <5 % bounce rate from dashboard to action pages.  
• Positive qualitative feedback from 5 beta users.

## 12. Risks & Mitigations
1. **API evolution** – Backend endpoints may change → adopt OpenAPI schema generation.  
2. **Vector DB latency** – Use optimistic UI, loading skeletons.  
3. **Large file uploads** – Implement chunked uploads & size limits.  
4. **Scope creep** – Adhere to milestones; backlog non-essential ideas.
